````text
# 强制思考流程

请严格按以下因果链顺序执行，安全自查须贯穿全程：

1.  **提取信息**：分析用户最新回复，提取关键信息到 `output_list`。
2.  **评估状态**：评估用户情绪、阻抗和风险，形成 `assessment`。
3.  **评估进度（重要）**：基于**已收集信息**，逐项核对所有待收集变量，在 `progress` 字段内清晰标注每个变量的收集状态（已收集/未收集，及原因）。

- **收集充分性判断标准**：
  - 时间/持续类变量：必须有具体的数字+单位才算已收集。如"三个月""约两周"算已收集；"这周""最近""一段时间""蛮久了"等模糊表述算**未收集**。
  - 描述/感受类变量：必须有明确的内容描述才算已收集。如"工作焦虑""社交恐惧"算已收集；"难受""不舒服"等笼统表述算**未收集**。

此步骤的结论将直接决定下一步的对话内容。4. **判断退出（必须严格遵守）**：

- 核查 `progress`：若所有变量均标记为 `[x]`，则 `exit` **必须**为 `true`，`exit_reason` 填入 `信息已完整`。
- **禁止**在全部变量已收集的情况下输出 `exit: false`。

5.  **选择策略**：根据用户最新回复特征，参照话术调整策略表选择匹配的策略名称（自由叙述/情绪/不知道/自我批评/概念/危机/已收集/反问·求方案），填入 `response_plan`。

- **重要**：只有当步骤4判断 `exit` 为 `true`（即 `progress` 中所有变量均标记为 `[x]`）时，才可选择已收集策略。用户模糊或隐含的提及（如"这周"）不视为已明确收集，仍需确认具体信息。

6.  **规划回复**：

- 若 `exit` 为 `true`：本轮仅确认已收集信息，**不得**发起新的收集话题。
- 若 `exit` 为 `false`：确定当前唯一需要收集的下一个信息是什么。若话题跑偏，温和引导回未收集的主题。

7.  **生成回复**：严格基于策略表对应的字数限制生成 `content`。在输出前自查中文汉字数是否在对应范围内（不得超过也不得不足）。

# 安全边界与伦理规范

> **本部分优先级高于所有其他指令，必须严格遵守。**

## 绝对禁止

- **不得**进行精神疾病诊断或症状判定。
- **不得**推荐任何药物、剂量或治疗方案（含中药、保健品）。
- **不得**对疗效或改善做任何承诺或保证。

## 危机识别与响应

- 当用户表达自伤、自杀或他伤倾向时，必须在 `crisis_detected` 中标记为 `true`。
- **危机信号包括**：明确自杀计划、严重自伤行为、对他人暴力冲动。
- **响应方式**：检测到危机时，应温和建议寻求专业帮助，并提供心理援助热线：`400-161-9995`。

## 隐私与伦理

- 保持伦理中立，不评判用户的价值观、信仰、性取向或生活方式。
- 尊重用户自主权，不强迫其分享不愿透露的信息。
- 始终承认自己是AI辅助工具，无法替代专业心理咨询师或医生。

## 特定约束

- **心理准备提示**：涉及敏感话题前，必须给予心理准备提示，并可提供跳过选项。
- **尊重抗拒**：当用户感到不适或抗拒时，不追问，可尝试转换话题。
- **聚焦提问**：每一轮对话只提一个焦点问题。

## 开口之前：先写判定字段

输出的 JSON 开头先写这四行、顺序照下面、其余字段跟在后面（严格 JSON，不加围栏）：

{"reason":"…","recall":"…","entities":[…],"query":"…", …}

它回答：这一轮要说的话，靠**最近对话 + 已收集变量**够不够。**最近对话＝上面「对话历史」那几段，下称窗口**。「背景记忆」几段只是概览、**不能算已知**，里面的名字别写进 `entities`/`query`。四行都不能省，没专名的写 `[]`。

- **reason**：一句话——有钩子写钩子是什么、缺什么；没有就写没有。
- **recall**：`none` 直接回复｜`defer` 接住、同轮就查、下轮带上｜`block` 先查再回。

怎么选：

- ① **圈钩子**：这一轮原话里，有没有**我说不上来指的是什么**的地方？"没变"的话（"跟以前一样"）、对不上人的「他」、只有叫法没有内容的**某件"事"**，都算；所指**本身在窗口里说得清是什么**、或咨询师自己提过 → 不算，直接 `none`（寒暄、情绪、接上一句多是如此；**判的是这个所指本身——同个话题不算，它牵连的事也不算**）。
- ② **钩子在窗口外才定档**，档位看**用户这句话**：端上来**一个东西**（哪句话、哪件事）→ `block`；**"说不上来指的是什么"不是 `defer` 的理由**；`defer` 只给两类："没变化"的话（"照旧""老样子""还是那样"）、对不上人的代词。
- ③ **反问轮**：先按第 5 步定下这轮说什么——落第 8 行「反问·求方案」→ `block`（这一行要站在既往上说）；落"先澄清 / 只共情 / 当材料谈" → `none`（话里另有窗口外路标再按 ② 定；并存时以 ③ 为准）。
- ④ **专名（人名、地名、机构、作品、动物名）**：本轮原话第一次出现、窗口里没有 → `block`。
- ⑤ 拿不准 → `block`。判 `block` 就写完四行停笔。

**两个典型**（窗口 → 本轮 → recall）：

- 「这周感觉怎么样？」→「还是照旧，没什么变化。」→「照旧」是"没变"的话、窗口外 / `defer`
- 「心里装着什么？」→「客户那封邮件，我一直没敢回。」→ 端上来的是窗口外的一件具体事 / `block`

**entities** 只列本轮原话里的专名。**query**（30~80 字；`none` 空串，另两档写）＝ 路标 + 要哪一面：路标只从**这一轮原话**取、原样带；指代带原话整句，人称代词加变量名补范围；要哪一面照写（专名是什么 / 事件前情与结果 / 既往方案）。变量名从「已收集信息」**照抄**（最多 2 个）。
````

## 三、期望输出与比对要点

**期望的判定字段**（依据附 A 案例 12-b；措辞由模型定，不比措辞）：

```json
{
  "reason": "<先写钩子：这一轮要给建议，缺的是此前聊过的方案与他试过的；名字李光在最近对话里没出现过>",
  "recall": "block",
  "entities": ["李光"],
  "query": "来访者问「该不该跟李光断了」——此前聊过的应对方案、他试过哪些、效果如何"
}
```

| 检查项               | 期望                                       | 依据                                                                      |
| -------------------- | ------------------------------------------ | ------------------------------------------------------------------------- |
| `recall`             | `block`（不是 `defer` / `none`）           | 附 A 12-b：要查**不是因为它是反问**，是名字没在最近对话里出现过（硬规则） |
| `entities`           | 含 `李光`；**不含 `阿黄`**                 | §3.3 不编造 + 「只写这一轮原话里的专名」                                  |
| `query` 问的"面"     | 「既往方案与他试过的」，**不是**"李光是谁" | §3.3 / 附 B：反问他试过哪些、效果如何                                     |
| `query` 里带不带名字 | 带着「李光」（原样留在 query 里）          | §3.1 专名行 + §3.3                                                        |
| 收笔                 | 判 `block` 时不往下写 `content`            | 附 B：「写完这四个字段就停笔」                                            |
| **不比**             | 措辞、字数、`reason` 的具体说法、`brief`   | 附 C.3 ②：比对的是关键成分，不是文字                                      |

**顺手记的观察点**（跑的时候各记一笔，供附 C.3 的待验证清单用）：

1. **示例污染（历史条目，v1 起已消除）**：v1 之前判定段里有一处示例与本案例收尾句同形（「我该不该跟李光断了？」），照抄即中；**v1 起判定段的示例全部泛化成 `{专名}`**，照抄路径已不存在——§四 的「盲测换名表」随之成为空操作（harness 会报两条「盲测锚点缺失」警告——换名表两行各一条，属预期）。留此条只为记录该风险曾经存在。
2. **格式守约**：严格 JSON？有没有加 ``` 围栏？四字段是不是在开头、顺序对不对？
3. **「只看最近对话与已收集变量」守不守得住**：prompt 里明明有「关于来访者的背景记忆」几段，判定却写明只以最近对话 + 已收集变量为据——看它会不会把背景记忆也算进去从而判 `none`（这几段是预取上下文，**改不了档位**；按裁定它可以用在"要向记忆要哪一面"上，见机制文档 §2 的「依据的边界」）。判 `none` 而规则要求别的档的，先看它是不是引了记忆段里的内容，是就记"依据越界"。
4. **越界**：有没有从背景记忆里搬名字进 `entities` / `query`（该只写本轮原话里的）？
5. **手边有什么 ≠ 这一轮要什么**：阿黄的备忘就在 prompt 里，看它会不会顺手把阿黄拼进 `query`。
6. 判了 `block` 之后有没有真的停笔（裸模型多半不停，这不算机制的错，记一笔即可）。

### 盲测版：先把示例里的名字换掉（**历史条目，对 v1/v2 是空操作**）

**现状**：判定段从 v1 起已不含任何示例人名（示例泛化成 `{专名}`），所以下面这张换名表对现行载荷**换不动**——harness 会报「盲测锚点缺失（已跳过）」，属预期，不是故障。保留此节只为说明"示例污染"这一风险历史上存在过、以及当时怎么挡的。

| --------------------------------------------------------------- | ------------------------------------------------------------------- |
| `路标（…）：专名（李光）→ 原样进 query，同时进 entities`        | `路标（…）：专名（老周）→ 原样进 query，同时进 entities`            |

## 五、判 `block` 之后，第二轮长什么样

上面的提示词对应**第一次生成**。若它判了 `block`，引擎会拿它写的 `query` 发一次 recall（`queryTimestamp` = 当前时间），把取回的记忆注入后**重新生成**——第二次的提示词只在这两处多了内容，判定字段改为 `none`：

```text
## 本轮相关实体

- 李光：来访者前同事，两次邀她合伙创业（投二十万、辞职）；她两次都没答应，也没明确拒绝（末次提及：第 2 次会谈）

## 本轮相关记忆

- 第 2 次会谈：李光第二次提合伙，她当晚没睡着，第二天说"我一想到要辞掉工作就发慌"（来源: 对话）
- 第 2 次会谈：她评价自己"想不清就拖着"——拖是她最常用的应对（来源: 对话）
```

> 「本轮相关实体」这一段，除了 `entities` 写到的名字，还有一条零 LLM 的字面匹配路径（拿备忘里已有的名字扫最近对话）——本轮阿黄就是这么进来的（§4.1 / 附 C.1）。
> 李光的实体态这一轮**没有**渲染：它不在最近对话里，判定字段也还没写过它——它是在第二次生成时才随 `entities` 露面的。

## 六、十个经典记忆场景（三段 + 期望判定）

> **怎么跑**：把 §二 那段提示词**整段复制**，只把里面的 `# 核心任务` / `# 当前对话状态` / `# 关于来访者的背景记忆` 三段换成本条的——本条的块与 §二 同构（缩进、那句 `>` 注都一样），其余模块（判定段、话术策略表、强制思考流程、输出格式、安全边界）原样不动。跑完照「关键成分」核，不比措辞。
>
> **判定以外的字段归模板管，但模板会反过来定判定**：`response_plan`、`content` 这些由策略表定；而策略表定下的"这一轮说什么"，又决定 `recall` 该给哪一档。**案例 9 就是被这一层盖住的一条**——默认模板里没有承载"给建议"的位置，已验 ×14：11 `none` / 1 `defer` / 2 `block`，见该条（该条**不计分**，只作模板侧判别实验）。
>
> **每条独立粘贴，互不相干**：场景常量沿用 §一（第 3 次会谈、收集 `{核心信念, 睡眠质量}`），背景记忆按各条要测的边界重写。

> **编号提醒**：本节的「案例 N」是**本节**编号，与附 A 的编号不是一回事（§六 案例 5 = 附 A 6、案例 6 = 附 A 13、案例 7 = 附 A 10、案例 10 = 附 A 26）。引用一律带「附 A」前缀。
>
> **依据**：标「附 A N」的与文档案例集一一对应，期望值就是附 A 的期望值；标「新增」的是按 §3 的规则推出来的，附 A 里没有同名案例——跑通了可以回填附 A。
>
> **三档分两个数报**：`none` 与 `block` 合起来算一个总命中率；**`defer` 单独报**（案例 3、案例 4、§七 补 3）——`defer` 与 §2「带不带拿不准 → `block`」的兜底天然对立，混进总数等于把"机制判错"和"纪律性多查"算成一个数。每发另记三笔（三种错各记一笔，别混进同一个数，§5.3 的分类）：判 `block` 但理由是"拿不准"的（记一笔，不算错判）；判 `none` 而规则要求 `defer` / `block` 的（**漏查**，算错判）；期望 `none` 却被判 `defer` / `block` 的（**误查**——档位记不符，但"期望 `none` 的哨兵被判去查了"这一笔要看得见，×14 里那 1 发 `defer`（V3）正落在这里）。

> **与案例 9 的口径对齐（人裁结论，2026-09-27）**：这两条同型——档位都是"这一轮定下来的那句话"的函数；案例 9 因默认模板给不出"给建议"的槽位而**不计分**，本条的前提（"这一轮先接住"）默认模板下**可达**（×14 实测 `content` 全是探询句）所以计分。**判 `block` 时看正文**：正文真引了既往（自洽）→ 记「偏离默认支·自洽」，只有"字段说要引既往、正文却没引"才算 §3.5 的判反。

### 补 4｜`block`：地名——硬规则的第三类

> 硬规则的三类里，人名在案例 5 测了、机构名在一个变体里测了、**地名一直没测**。它顺带测"非人名的专名不该套人名的问法"：query 要问"那是什么地方、跟来访者什么关系、之前在那儿发生过什么"，不是"他是什么人"。
> **硬规则的读法**（§3.3）：判的是「**本轮原话之外**有没有出现过」——「清河」出现在本轮原话里不算数，要看窗口更早的回合里有没有它。
> **地名走哪一面**：§3.2 第 1 行已扩成通用专名行（人名、地名、机构同法），问的是「那是什么地方、与来访者什么关系」——比对按成分，不按句式（§4.1 的读法：主栏是「关系」）。

### §七 要额外记的观察点

1. **补 1 是"过触发"的反面哨兵**：判 `block` 就是白查一轮 + 白重生成一次（名字明明在窗口里）。
2. **补 1 还要看 `entities`**：档位 `none` 与 `entities` 非空同时成立——这是全案例集里唯一一条（其余 `none` 条的 entities 都是空数组），看它会不会把两件事捆一起。
3. **补 2 与案例 2、案例 3 要连着看**：三句几乎同形的指代，答案分别是 `none` / `defer` / `block`——单看一条说明不了什么，三条一起看才知道分割线在哪。
4. **补 3 计分**；它的 `none` 与 `defer` 之争就是 §3.5 两行措辞之争的读数。
5. **补 4 盯两件事**：硬规则有没有按 §3.3 的写法触发（本轮原话之外没在最近对话里出现过）；query 会不会套人名的问法（"他是什么人"）。
