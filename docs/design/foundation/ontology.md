## 1. 任务层：咨询师在会谈中要完成什么任务

> 任务层是引擎智能的锚：**新智能点从任务层的缺口来**——任务层拆出一个新任务，才有对应的 story（rhythm §8）。

### 1.1 顶层分解

咨询师在会谈中同时运转两种思维、共享一个议程对象，每轮开始还做一次记忆联想（[意识系统设计](../consciousness/consciousness-system.md) §1.1、§2.1）：

| 任务         | 英文                 | 一句话定义                                               | 机制承载文档                                                                                     |
| ------------ | -------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| **主线思维** | Main-thread Thinking | 按议程逐项执行，回应来访者                               | [话题单元建模](../topic/topic-unit-modeling.md)                                                  |
| **意图思维** | Intention Thinking   | 边执行边观察：监测信号，判断议程是否需调整并干预         | [意识系统设计](../consciousness/consciousness-system.md)                                         |
| **话题队列** | Topic Queue          | 两条思维共享的议程对象：生成（脚本展开）→ 执行 → 调整    | [话题单元建模](../topic/topic-unit-modeling.md)（判断一~三、不变量一~三）                        |
| **记忆联想** | Recall               | 每轮开始时用用户原话检索历史记忆，同时服务主线和意图思维 | [记忆框架](../memory/memory-framework.md) · [ai_ask 记忆调用](../memory/ai-ask-memory-recall.md) |

> 注：话题队列不是"思维"，是两条思维共同操作的共享对象；rhythm §8 把它列在任务层，此处照录，账本归属确认见 §5 开放问题。

### 1.2 主线思维的分解

主线思维 = 取队首话题 → 执行其动作序列 → 完成后取下一个。动作原子即其分解粒度（[话题单元建模](../topic/topic-unit-modeling.md) §2）：

| 子任务     | 承载动作   | 一句话                                                        |
| ---------- | ---------- | ------------------------------------------------------------- |
| 收集信息   | `ai_ask`   | 生成问题 → 等待输入 → 提取变量 → 判断何时退出（含退出决策）   |
| 解释与告知 | `ai_say`   | 把信息组织成适合这个来访者的表达                              |
| 内部推理   | `ai_think` | 分析已有信息，结论写入变量，不对外输出                        |
| 引导填表   | `ai_fill`  | 呈现结构化表单 → 引导填写 → 校验 → 存储                       |
| 图形呈现   | `ai_draw`  | 待评审：倾向降为 `ai_say` 的 format 参数（话题单元建模 §5.4） |

### 1.3 意图思维的分解

意图思维 = 观察 → 判断 → 干预（[意识系统设计](../consciousness/consciousness-system.md) §2）：

1. **观察**：一组意识各从一个角度观察对话。内置意识（始终加载）：`process_quality` 流程质量、`strategy_adaptation` 策略调适；脚本定义意识（按 Phase/Topic 加载）：`emotion_trajectory` 情绪轨迹、`contradiction_detect` 叙事矛盾、`resistance_monitor` 阻抗监测、情绪否定检测等。
2. **判断**：各意识判定信号是否出现（直接识别 / 累计识别）、严重度、是否触发；多意识同时触发时仲裁冲突（§3 推理层）。
3. **干预**：轻量——向主线提示词注入策略建议；重量——调整话题队列（六种队列操作）或话题内动作。

## 2. 领域层（本体）：任务涉及的概念及其关系

> 维护纪律（rhythm §8）：**新概念必须有任务锚**——每个词都回答"哪个任务需要它"；写不出来就是造词，不进本体。下表所有概念均来自现有文档。

### 2.1 概念表

| 概念         | 英文                     | 定义（出处）                                                                  | 任务锚                                         |
| ------------ | ------------------------ | ----------------------------------------------------------------------------- | ---------------------------------------------- |
| 阻抗         | Resistance               | 来访者回避或抵触当前话题（resistance_monitor）                                | 意图思维·阻抗监测                              |
| 情绪否定     | Emotion Negation         | 被追问情绪后收回/否定自己的情绪表达（意识系统 §1.2 案例）                     | 意图思维·情绪否定检测                          |
| 情绪轨迹     | Emotion Trajectory       | 来访者在阶段内情绪表达的变化模式（emotion_trajectory）                        | 意图思维·情绪轨迹检测                          |
| 叙事矛盾     | Narrative Contradiction  | 来访者对关键关系/事件的前后表述不一致（contradiction_detect）                 | 意图思维·叙事矛盾检测                          |
| 危机信号     | Crisis Signal            | 安全相关信号（如自杀意念），触发紧急插入危机评估话题（话题单元建模 §4.2）     | 意图思维·紧急干预                              |
| 时间压力     | Time Pressure            | 会谈时间不足，触发深度切换/重排（话题单元建模 §4.2）                          | 意图思维·调度                                  |
| 语义完整性   | Utterance Completeness   | 用户本轮输入是"讲到一半"还是"说完了完整意思"（utterance_complete 标记）       | 意图思维·判断前置门控                          |
| 自我归因句式 | Self-attribution Pattern | "是我不好""我太敏感了"等跨轮重复的自我归因模式（自责句式检测，意识系统 §1.2） | 意图思维·自责句式检测                          |
| 证据链完整   | Evidence Completeness    | ai_ask 收集的信息是否足以结束当前提问（退出决策）                             | 主线思维·收集信息（术语已登记 UL「退出决策」） |

### 2.2 概念关系（简图）

```
危机信号 ──最高优先级──▶ 话题队列.interrupt（紧急插入）
时间压力 ──▶ 话题队列.depth / reorder
阻抗     ──▶ 干预：插入情绪安抚话题
情绪否定 ──▶ 干预：提示词注入（"把情绪还给用户"）
叙事矛盾 / 情绪轨迹 / 自我归因句式 ──▶ 干预：提示词注入或慢思考
语义完整性 = false ──▶ 意图思维本轮跳过
证据链完整 = true ──▶ 主线思维·收集信息结束
```

## 3. 推理层：任务怎么用概念做判断

| 判断         | 规则                                                                                                                                           | 出处                      |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| 触发判断     | 直接识别（单轮模式）vs 累计识别（min_rounds 跨轮）；cooldown_rounds 冷却；severity_threshold 严重度门槛；utterance_complete 门控               | 意识系统 §2.2、§2.3.2     |
| 干预分级判断 | 轻量（证据单轮足够，提示词注入）vs 重量（跨轮累积证据，队列操作/动作调整），由 intervention.mode + 严重度路由                                  | 意识系统 §2.2、§2.4       |
| 议程调整判断 | 六种队列操作：insert / interrupt / cancel / reorder / depth / urgency；多操作并发优先级：interrupt > cancel > depth > insert > urgency+reorder | 话题单元建模 §4.2、附录 A |
| 冲突仲裁判断 | 多意识同时触发 → 仲裁 LLM 检查冲突、按严重度排序、合并互补建议                                                                                 | 意识系统 §2.1             |
| 退出判断     | ai_ask 何时结束收集：规则评估 + LLM 语义判断                                                                                                   | UL「退出决策」            |

## 4. 与平台侧 UL 的桥接现状

- **已在 UL 登记**：意识、轻量干预、重量干预、调整、中断、内置意识、脚本定义意识、退出决策（UL §三、§六）。
- **待登记**（本体概念变成代码类名/枚举/字段时按规则登记）：阻抗、情绪否定、情绪轨迹、叙事矛盾、危机信号、时间压力、语义完整性、自我归因句式。
- **记忆机制概念不进本体**：三网络 + mental model、快慢通道等属于记忆框架的机制层（[memory-framework](../memory/memory-framework.md)，ADR 005 校准），与咨询任务知识的边界见 §5。

## 5. 开放问题（评审时逐条过）

1. **任务层顶层分解**是否符合咨询实践（主线/意图/话题队列/记忆联想）——你的审核门。
2. **阻抗 vs 情绪否定的边界**：rhythm §11 迭代回顾已预见二者边界模糊，本体重建时重新划定。
3. **话题队列的账本归属**：README 索引把它归「地图 · 领域建模」，本文档任务层引用而非吸收——两本账的边界是否成立。
4. **记忆联想是否顶层任务**：从意识系统 §2.1 每轮运转序列提取，rhythm §8 任务层未点名——待确认。
5. **概念命名统一**：「自责句式检测」（意识名）与「自我归因句式」（概念名）、「情绪否定检测」与「情绪否定」——意识名与概念名是否各留一份，待确认。
