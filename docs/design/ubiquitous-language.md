# HeartRule 通用语言（Ubiquitous Language）

> **定位**：HeartRule 系统所有领域的通用术语表。每个术语经过了心理咨询、法律顾问、战略咨询、营养咨询四个领域的交叉检验——四个领域的咨询师都能用这些词自然描述自己的工作过程。
>
> 本文档是 DDD 战略设计的产物之一，与 `docs/ddd/` 的 strategic-design、context-map 配套使用。按[开发节奏系统](../process/development-rhythm.md)，它是**代码术语的唯一登记处**：本体概念变成代码里的类名/枚举/字段时，在此登记一行（指向[本体文档](ontology.md)），保证代码术语只有一份账。
>
> **使用者**：设计文档、代码命名、UI 文案、团队沟通。
>
> **版本**：v1.1.0
> **创建**：2026-07-21

---

## 核心隐喻：小笔记本

> 咨询师在会谈前，翻开**脚本**，找到适合当前来访者的阶段和话题。把来访者的具体情况（**变量**）代入——这个将通用脚本适配到具体来访者的过程叫**个案化**——形成一份个性化的话题清单，写在**小笔记本**（议程）上。整个准备工作叫**会谈准备**。
>
> 会谈中，按小笔记本上的**话题**逐一执行**动作**。同时保持**意识**——来访者讲了重要线索？时间不够？来访者抗拒当前话题？
>
> 需要**调整**：在小笔记本上划掉、插入、重排、改优先级。紧急情况可以**中断**当前话题。
>
> 会谈结束时笔记本上还有没聊的？记下来，**遗留**到下次会谈准备时参考。

## 一、咨询过程

> 所属限界上下文：**咨询会话（Consulting Session，核心域）**

| 术语     | 英文    | 定义                                                                                                                              |
| -------- | ------- | --------------------------------------------------------------------------------------------------------------------------------- |
| **会谈** | Session | 从开始到结束的一次完整咨询过程。包含议程准备、逐一执行、过程觉察、收尾总结                                                        |
| **脚本** | Script  | 预先写好的 YAML 流程模板——阶段 → 话题 → 动作。是咨询经验的结晶，可跨来访者复用                                                    |
| **阶段** | Phase   | 脚本中的大块划分。如"开场建立关系""评估与分析""干预执行""总结与收尾"。每个阶段有目标、时间预算、可声明意识脚本                    |
| **话题** | Topic   | 阶段中一个完整的讨论单元。是最小的可复用经验单位——"要达成什么目标 + 怎么做（动作序列）"。如"收集主诉""探索触发模式""认知心理教育" |
| **动作** | Action  | 话题内的最小执行单元。一次原子级的交互操作。按行为模式分为四种：                                                                  |
|          | Ask     | 提问。向来访者提出问题，等待输入，从回答中提取变量                                                                                |
|          | Say     | 讲述。向来访者介绍、解释、告知信息。不等待输入                                                                                    |
|          | Think   | 思考。咨询师内部思考和分析，不对外输出。产出写入变量                                                                              |
|          | Form    | 填表。引导来访者填写结构化表单，校验后存入变量                                                                                    |

## 二、个案化与准备

> 所属限界上下文：**咨询会话（Consulting Session，核心域）**

| 术语         | 英文                | 定义                                                                                                                 |
| ------------ | ------------------- | -------------------------------------------------------------------------------------------------------------------- |
| **变量**     | Variable            | 来访者的具体信息。年龄、症状、偏好、历史事件、家庭结构等。变量是脚本通用性和会谈个性化之间的桥梁                     |
| **个案化**   | Personalization     | 会谈准备的核心动作：把脚本代入来访者变量，将通用的话题转成该来访者专属的话题实例。包括变量代换、`expand_by` 列表展开 |
| **会谈准备** | Session Preparation | 会谈前把脚本个案化、形成议程的完整过程。包括变量代换、列表展开、各话题时间估算、阶段时间预算累计                     |
| **议程**     | Agenda              | 会谈准备的输出——一份可变的话题执行清单。每个条目有预估时长、紧急度、重要性、深度标记。意识层可在会谈中随时调整议程   |
| **议程条目** | Agenda Entry        | 议程中的一项。包含：话题 ID、来源（脚本/技术脚本/即兴）、动作列表、状态、紧急度、重要性、深度版本、预估时长          |

## 三、执行与觉察

> 所属限界上下文：**咨询会话（Consulting Session，核心域）**

| 术语             | 英文                         | 定义                                                                                                                       |
| ---------------- | ---------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| **意识**         | Consciousness                | 咨询师在会谈中"边执行边观察"的能力。不直接对来访者说话，而是在背后观察对话、监测信号、积累判断。必要时干预议程             |
| **轻量干预**     | Light Intervention           | 向当前动作的提示词注入策略建议，影响下一轮的表达方式。不改变议程。触发门槛低                                               |
| **重量干预**     | Heavy Intervention           | 调整议程本身——插入、取消、重排话题、切换深度版本。触发门槛高，需跨轮累积证据                                               |
| **调整**         | Adjustment                   | 意识层对议程的六种操作：插入话题、取消话题、重排顺序、切换深度版本、变更紧急度                                             |
| **中断**         | Interrupt                    | 一种紧急调整：当前话题暂停（保存执行状态），紧急话题插到队首。完成后再判断是否恢复原话题。同一时刻只冻结一个话题，不可嵌套 |
| **内置意识**     | Built-in Consciousness       | 始终运行，无需在脚本中声明。如流程质量监测（`process_quality`）、执行策略调适（`strategy_adaptation`）                     |
| **脚本定义意识** | Script-defined Consciousness | 在脚本的阶段或话题级别声明，按需加载。如情绪轨迹检测、叙事矛盾检测、阻抗监测                                               |

## 四、参会人

> 所属限界上下文：**咨询会话（Consulting Session，核心域）**

| 术语       | 英文       | 定义                                                                  |
| ---------- | ---------- | --------------------------------------------------------------------- |
| **来访者** | Client     | 咨询的接受方。在不同领域叫法不同，统一用"来访者"                      |
| **咨询师** | Consultant | 咨询的提供方。是脚本的设计者，也是会谈的执行者。AI 是其学徒和执行助手 |

## 五、会谈生命周期

> 所属限界上下文：**咨询会话（Consulting Session，核心域）**

| 术语         | 英文             | 定义                                                                                                                              |
| ------------ | ---------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| **遗留话题** | Carryover        | 本次会谈因时间不足或其他原因未完成的话题，保留到下次会谈准备时参考                                                                |
| **议程展开** | Agenda Expansion | 脚本中声明 `expand_by` 的话题，按列表变量逐项个案化为多个议程条目。变量已有值时在会谈准备时立即展开；变量在会谈中才就绪时动态追加 |
| **深度版本** | Depth            | 话题的执行深度：快速版（要点过一遍）、标准版（完整流程）、详细版（深入探索）。意识层可在时间压力下切换版本                        |
| **紧急度**   | Urgency          | 话题的执行优先级，决定议程中的先后顺序。值越高越靠前。意识层可通过 `setUrgency` 动态调整                                          |
| **重要性**   | Importance       | 话题的内在价值，决定时间压力下的取舍：低→cancel 延后，中→quick 压缩，高→保留完整时间移到下次                                      |

## 六、技术架构（代码层面）

这些术语不出现在用户界面，仅用于代码和架构讨论。所属上下文逐行标注；"架构通用"指六边形架构词汇，不属于特定上下文。

| 术语           | 英文                | 所属上下文 | 定义                                                                                         |
| -------------- | ------------------- | ---------- | -------------------------------------------------------------------------------------------- |
| **引擎**       | Engine              | 横跨       | 执行会谈的核心组件。六个引擎：脚本执行、LLM 编排、变量提取、变量作用域、退出决策、提示词模板 |
| **端口**       | Port                | 架构通用   | 引擎与外部交互的接口定义。如 `ILLMProvider`、`MemoryRepository`、`TemplateProvider`          |
| **适配器**     | Adapter             | 架构通用   | 端口的具体实现。如 `OpenAIProvider`、`HindsightMemoryAdapter`、`DatabaseTemplateProvider`    |
| **Provider**   | Provider            | LLM 集成   | LLM 服务提供方。如 OpenAI、DeepSeek、火山引擎                                                |
| **变量作用域** | Variable Scope      | 变量系统   | 四层优先级：话题 > 阶段 > 会谈 > 全局。同名变量按此顺序查找                                  |
| **变量提取**   | Variable Extraction | 变量系统   | 从来访者回答中提取结构化变量。三种方法：直接类型转换、正则模式匹配、LLM 语义提取             |
| **退出决策**   | Exit Decision       | 咨询会话   | 判断当前动作是否可以结束。规则评估 + LLM 语义判断                                            |
| **提示词模板** | Prompt Template     | 提示词工程 | 两层模板体系：Custom（领域定制）优先于 Default（系统默认）                                   |

## 七、领域驱动设计术语

> 本节是 DDD 方法自身的术语（元词汇），不属于任何业务限界上下文。

| 术语            | 英文             | 定义                                                                                                                                                                                                          |
| --------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **限界上下文**  | Bounded Context  | 领域模型的明确边界。HeartRule 定义了 5 个限界上下文 + 1 个通用子域：咨询会话（核心）、变量系统、会话记忆、提示词工程、脚本创作 + LLM 集成（通用子域）。完整领域语言清单见 `docs/ddd/strategic-design.md` §1.3 |
| **聚合**        | Aggregate        | 一组相关对象的集合，有聚合根。会话（Session）是唯一的聚合根                                                                                                                                                   |
| **实体**        | Entity           | 有唯一标识的领域对象。如会话实体                                                                                                                                                                              |
| **值对象**      | Value Object     | 不可变的领域对象。如话题、动作配置                                                                                                                                                                            |
| **领域服务**    | Domain Service   | 执行领域逻辑的无状态服务。如退出决策引擎                                                                                                                                                                      |
| **领域事件**    | Domain Event     | 领域状态变化的事件。如话题完成、变量更新                                                                                                                                                                      |
| **端口-适配器** | Ports & Adapters | 六边形架构：核心引擎通过端口定义合约，适配器实现合约对接外部系统                                                                                                                                              |
