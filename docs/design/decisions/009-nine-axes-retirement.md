# 009 — 九轴文档退场：通用调取抽象路线放弃，三路查询明确弃

## 背景

`memory-retrieval-types.md`（九轴模型）的原始使命是「跳出具体咨询动作，找通用的记忆调取」——该路线已放弃：检索机制的实现收敛为 ai_ask 一条线（006 → 008 封板），权威在 [ai-ask-memory-recall.md](../memory/ai-ask-memory-recall.md)，自足。

006 曾把它降为「坐标系 / 描述语言」保留（决策 1），用途是给未来的检索方案做比较与校验。此后三周，这个语言没有被用过一次：没有一处新设计或代码以轴取值描述检索方案；指向它的活指针只剩 §2.11 一处（backlog 故事与 ai-ask 附 C.5）。而 006 自立的另一条原则——「抽象从消费者向上生长，不由坐标系向下规定」——恰恰说明后续消费者（意识层慢通道、ai_think）应从自身长出词汇，不该被预置坐标塑形。

另有两处使这份封板稿不宜再留：

1. **落地状态层是抄写、且会过期**：§2.3 的「v0.9.1 落地状态」列、§3.2 落地段、§5.1 校验表，是 004 结论在本文档的再抄写，内容随 Hindsight SDK 版本过期——封板文档背着会过期的台账，读者无法据此判断机制。
2. **机制挂在桩上**：§4.1 把 Layer 3（深度分析）的载体指定为 `ai_think`，而 ai_think 目前是空壳（审计 [deep-dive-execution-core](../../audit/deep-dive-execution-core.md) 已记为「封板文档把机制挂在桩上」）。

2026-09-29 人裁：整篇退场（搬 docs-archive）；三路查询整条明确弃。

## 决策

### 决策 1：整篇退场，搬 docs-archive

**结论**：本稿不再留在 `docs/design/`——整篇搬 `docs-archive/architecture/`，按归档惯例标 `archived` / `historical`（只作历史参考，复活需人确认）。设计 README 记忆线索引行标 `superseded` 并指向归档稿；九轴不再作为检索层的描述语言或检查表。

**理由**：留着它 = 设计树里一份没人读、读不懂、还可能被误当权威的稿。归档而非删除：004/005 的校准过程与九轴原始设计保留可查。

### 决策 2：三路查询明确弃（取代 006 决策 2 后半）

**结论**：006 决策 2 的「『类似事件 / 关联事件』三路扩展待实证、默认关闭」改为**明确弃**——不做实证、不进实现、不设预留。单路查询继续是快通道的行为本身，且不再有候补扩展路线。backlog 故事「三路查询实证：类似/关联事件视角的命中率对比验证（默认关闭，证据通过才开启）」撤下、记入已关闭；`ai-ask-memory-recall.md` 附 C.5 的三路一行随之删除（分段检索保留）。

**理由**：「待实证」挂账的前提是将来会做；方向本身随九轴退场失去描述语言与设计稿。将来若出现查询扩展的真实需求，按 006 决策 1 的方向从消费者侧重设计——本条不封这条路，只封「挂着等实证」这个状态。

### 决策 3：两条遗留一并了结

**结论**：① §4.1「Layer 3 载体 = ai_think、perspectives 映射为轴取值」作废——ai_think 的检索需求（若有）将来从 ai_think 侧生长；② §5 表末「极少『必须查』场景 → 脚本显式声明（语法待定义）」明确弃——不设预留语法。

**理由**：两条都以九轴为参照物；参照物退场，它们失去落脚。

## 后果

- **正面**：设计树只留权威文档；「封板文档挂桩」「会过期的落地台账」两类问题随之消解；检索层不再背「通用语言」的预设负担——消费者按需生长。
- **代价**：将来设计新检索消费者时没有现成共享词汇表——需要时归档稿可作历史参考，或另立新稿。三路扩展未测即弃；机会成本由「该路线无消费者」承担。
- **同步清单**（执行项）：设计 README（索引行 + 注册表）；backlog（撤故事 + 已关闭一行）；ai-ask 附 C.5；`.claude/agents/memory-plan.md` 必读清单；006 关联行链接机械校正（ADR 正文不动）。审计快照不改（其自身有退场条件）。
- **红线**：不涉及（D1–D6 未挂本稿）。
