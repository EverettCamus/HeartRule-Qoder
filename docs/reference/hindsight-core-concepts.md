## 一句话总结

**Hindsight 的核心理念是：记忆应该是推理的"一等公民"，而不是把检索到的文本块塞进 prompt 的薄适配层。** 这是对 RAG（检索增强生成）的根本性批判和替代。

---

## 核心洞察：RAG 的三个致命缺陷

Hindsight 的设计动机来自对 RAG 的反思：

RAG 的工作方式: 用户问题 → 向量搜索 → 找到相关文本块 → 拼进 prompt → LLM 回答

RAG 的问题:

1. **所有记忆没有区分** —— "用户说过他焦虑"和"咨询师判断这是社交焦虑"在向量空间中都是相似的文本,但一个是"证据",一个是"推论"
2. **没有时间感** —— "用户上周说"和"用户三个月前说"被同等对待
3. **没有信念更新** —— 新证据来了,旧认知不会自动修正

Hindsight 的回答: 记忆不是文本的堆砌，而是一个有结构、有时间维度、能自我进化的认知体系。

## 四大网络：记忆的认知分类

Hindsight 按照"知道什么 vs 相信什么"将记忆分为四个网络：

```
                    ┌─────────────────────────────┐
                    │       Observation Network     │
                    │   综合摘要 (偏好中立)           │
                    └─────────────┬───────────────┘
                                  │ 从 W 和 B 蒸馏而来
                ┌─────────────────┼─────────────────┐
                │                 │                 │
    ┌───────────▼──────┐  ┌──────▼──────────┐  ┌──▼──────────────┐
    │  World Network   │  │ Experience Net  │  │ Opinion Network │
    │  客观事实 (W)     │  │ 亲身经历 (B)    │  │ 主观信念 (O)    │
    └──────────────────┘  └─────────────────┘  └─────────────────┘
```

| 网络                | 内容                                                | 示例                                                  |
| ------------------- | --------------------------------------------------- | ----------------------------------------------------- |
| **World (W)**       | 客观的第三方事实                                    | "巴黎是法国首都"、"爱丽丝在Google工作"                |
| **Experience (B)**  | Agent 自身行动和互动的第一人称记录                  | "我上周向爱丽丝推荐了优胜美地"、"我摸了炉子,真的很疼" |
| **Opinion (O)**     | 带有信心分数 c∈[0,1] 和时间戳的主观信念; 可动态更新 | "Python 是数据科学的最佳语言" (信心: 0.85)            |
| **Observation (S)** | 从 W 和 B 蒸馏出的、偏好中立的实体摘要              | "爱丽丝是Google的ML工程师"                            |

**认知清晰性（Epistemic Clarity）** 是核心理念：你明确地知道哪些是事实、哪些是经历、哪些是判断。

### 映射到心理咨询领域

```
World Network (W):
  "用户被诊断为广泛性焦虑障碍"
  "CBT的认知重构技术要求识别自动化思维"

Experience Network (B):
  "第3次会谈: 咨询师引导用户探索'被领导批评→心跳加速→我什么都不行'的认知链"
  "第5次会谈: 用户首次主动使用思维记录表,记录了3个自动化思维"

Opinion Network (O):
  "咨询师评估: 用户的焦虑核心是'不被认可'的深层信念 (信心: 0.78)"
  "假设: 用户的工作焦虑与其父亲的高期望有关 (信心: 0.45)"
    ↑ 信心较低,随着更多证据可能上升或下降

Observation Network (S):
  "用户与父亲关系的综合画像: 疏远、有未解决的期望冲突,但用户表达了修复意愿"
```

Opinion Network 中的假设代表**工作假设** —— 不是事实，而是有待验证的判断。随着更多会谈证据出现，信心会上调或下调。这与心理咨询中"形成假设 → 收集证据 → 修正假设"的临床思维完全吻合。

## 三个操作：记住 → 召回 → 反思

### retain ("记住")

```
原始对话 → LLM提取叙事事实 → 实体解析 → 构建图谱边 → 分类到四个网络 → 存储
```

- LLM 提取的是**完整叙事事实**（保留跨轮因果链），而非句子级片段
- 实体解析将 "Alice"、"Alice Chen"、"the new PM" 规范化为同一实体
- 图谱边有四种类型（见下文）

### recall ("召回")

4 路并行检索:

| 策略         | 机制                       | 擅长                               |
| ------------ | -------------------------- | ---------------------------------- |
| **语义搜索** | HNSW 向量相似度            | 释义、概念匹配                     |
| **关键词**   | BM25 精确匹配              | 专有名词、术语                     |
| **图谱遍历** | 沿实体/因果/时间边扩散激活 | 间接相关信息的多跳发现             |
| **时间过滤** | 日期解析 + 范围过滤        | "六月发生了什么?" / "在他辞职之前" |

结果通过 **RRF (Reciprocal Rank Fusion)** 融合，再经**交叉编码器**重排序，最后按 **token 预算**（而非 top-K）截断。

### reflect ("反思")

**Hindsight 最独特的操作** —— 跨所有记忆进行 LLM 综合推理：

- "回顾过去5次会谈，用户的焦虑触发因素呈现什么模式？"
- "用户对母亲的态度从第1次到第6次会谈有什么变化？"
- "哪些早期的咨询假设已经被后续证据所修正？"

RAG 只能找到"关于焦虑的文本块"，无法进行跨记忆的综合分析。

## 知识图谱：四种边类型

记忆之间通过图 G=(V,E) 连接，四种边类型：

| 边类型       | 含义     | 咨询场景示例                                           |
| ------------ | -------- | ------------------------------------------------------ |
| **temporal** | 时间先后 | "用户先报告失眠,一个月后报告睡眠改善"                  |
| **semantic** | 语义相似 | "老板看我不顺眼"和"领导总是挑我毛病"指同一意思         |
| **entity**   | 共享实体 | "母亲"连接了童年叙述、当前冲突、支持系统三个维度的记忆 |
| **causal**   | 因果关系 | "被批评(因) → 心跳加速(果) → '我什么都不行'(认知)"     |

支持**多跳推理**：

```
查询："用户的社交回避行为与什么有关？"
  → entity 边: "社交回避" → 找到所有提到社交场合的记忆
  → causal 边: 跟踪"社交场合 → 焦虑 → 回避行为"的因果链
  → temporal 边: 确定回避行为从何时开始加重
  → semantic 边: 找到虽然没说"回避"但描述了类似行为的句子
```

## 观点信心分数的动态演化

每个 Opinion 是三元组 `(text, confidence, timestamp)`:

`c ∈ [0,1]` 代表信念强度

当新证据到达时:

| 新证据与旧观点的关系 | 信心变化              | 咨询场景                                                            |
| -------------------- | --------------------- | ------------------------------------------------------------------- |
| **强化**             | c' = min(c + α, 1.0)  | "用户又一次将工作压力描述为焦虑的主要来源"                          |
| **削弱**             | c' = max(c - α, 0.0)  | "用户说最近工作很顺,但焦虑感不减"                                   |
| **直接矛盾**         | c' = max(c - 2α, 0.0) | "用户在第5次会谈说与母亲关系很好,第8次详细描述了母亲的长期情感忽视" |

**核心精妙之处**: 不是硬性的"正确/错误"判断，而是渐进式的信心调整。与心理咨询中的临床判断过程一致 —— 工作假设随着对来访者的深入了解而不断微调，很少有戏剧性的"推翻"，更多的是"修正"和"细化"。

## 行为参数：推理风格的一致性

CARA 组件引入可配置的**行为参数** `Θ = (S, L, E, β)`:

| 参数                    | 范围 | 含义                     | 咨询场景类比                                 |
| ----------------------- | ---- | ------------------------ | -------------------------------------------- |
| **Skepticism** (怀疑度) | 1-5  | 对新证据的审慎程度       | "来访者说自己没事了"——信以为真还是深入探查？ |
| **Literalism** (字面度) | 1-5  | 严格按字面 vs 读言外之意 | "我挺好的"——字面意思还是隐含负面情绪？       |
| **Empathy** (共情度)    | 1-5  | 推理时的情感关注程度     | 高共情适合支持性咨询,低共情适合行为激活      |
| **Bias** (偏差强度)     | 0-1  | 事实导向 vs 偏好导向     | 0 = 纯事实推理, 1 = 按偏好推理               |

这些参数被"语言化"后注入 LLM system prompt，确保跨会话推理风格一致 —— 对心理咨询中保持 AI 咨询师"人格"的连续性很重要。

## 两大核心组件

### TEMPR — Temporal Entity Memory Priming Retrieval

实现 **retain** 和 **recall**:

- 叙事事实提取（保留跨轮因果链，非句子级片段）
- 嵌入生成（时间增强文本 → 向量）
- 实体解析（字符串相似度 + 共现 + 时间邻近度）
- 图谱边构建（4种类型）
- 观点强化/削弱

### CARA — Coherent Adaptive Reasoning Agents

实现 **reflect**:

- 行为参数注入
- 观点形成与信心更新
- 背景信息合并（新信息优先、第一人称统一、非冲突细节保留）

| 配置                      | LongMemEval 准确率 |
| ------------------------- | ------------------ |
| 全上下文 OSS-20B (无记忆) | 39.0%              |
| 全上下文 GPT-4o (无记忆)  | 60.2%              |

核心发现：**20B 模型 + Hindsight (83.6%) 超越全上下文 GPT-4o (60.2%)** —— 架构比模型规模更重要。

## 四大设计原则

1. **认知清晰性（Epistemic Clarity）**: 事实、观察、信念在结构上明确分离 —— 你知道 Agent *知道*什么 vs *相信*什么
2. **时间感知（Temporal Awareness）**: 每条记忆带有 `(τ_start, τ_end, τ_mention)` 三元时间戳
3. **实体感知推理（Entity-Aware Reasoning）**: 四种边类型的记忆图谱支持多跳发现
4. **偏好一致性（Preference Consistency）**: 行为参数确保 Agent 跨会话保持稳定推理风格，同时允许信念演化

## RAG vs Memory 对比

| 维度           | RAG                    | Hindsight                           |
| -------------- | ---------------------- | ----------------------------------- |
| **信息处理**   | 所有检索信息无差别对待 | 四网络分离事实、经历、信念、观察    |
| **认知区分**   | 不区分证据 vs 推论     | 显式结构分离                        |
| **时间推理**   | 无原生时间感知         | 双时间戳、时间过滤、新近度衰减      |
| **多跳推理**   | 限于检索到的文本块     | 沿实体/因果/时间边的图谱遍历        |
| **信念演化**   | 无机制                 | 信心分数 + 强化/削弱更新            |
| **偏好一致性** | 局部合理、全局不一致   | 行为参数确保稳定风格                |
| **检索策略**   | 单一向量相似度         | 四路并行 + RRF融合 + 交叉编码器重排 |

## 对 HeartRule 的启示：值得借鉴的设计理念

即使自建记忆系统，以下 Hindsight 的理念可以直接融入 HeartRule:

1. **区分"证据"和"推论"** —— 用户说的 vs 咨询师判断的，应有明确的结构分界
2. **观点 + 信心分数 + 时间戳** —— 咨询师的评估不是静态的，随着新证据动态演化
3. **四种边类型的知识图谱** —— 时间边、语义边、实体边、因果边，使记忆之间不再是孤岛
4. **reflect 操作** —— 定期跨记忆综合反思，而不是每次只是"找相关内容"
5. **行为参数的连续性** —— AI 咨询师在整个治疗关系中保持一致的推理风格

这些理念的实现不依赖 Hindsight 的代码。它们本质上是对"记忆系统应该如何组织"的思考方式。
