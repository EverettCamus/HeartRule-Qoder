# Spec 模板（HeartRule 固定节）

> 文件名：`docs/superpowers/specs/YYYY-MM-DD-<slug>-design.md`。以下七节为必含节；引擎机制的 spec 额外把锚（一句话价值 + 任务锚）写进开头（rhythm §8 落点 4）。

```markdown
# <标题> Spec

## 1. 功能描述

这个 story 要交付什么，一句话价值 + 用户场景。

## 2. 验收标准（Given-When-Then）

- **正例**：Given … When … Then …（至少一条）
- **负例**：Given … When … Then …（至少一条，覆盖边界/异常）

## 3. 数据模型

涉及的实体/值对象/存储结构。

## 4. 接口定义

端口、路由、函数签名、消息契约。

## 5. 领域模型片段（DDD 战术设计落点）

本 story 涉及的限界上下文内的战术设计：聚合/实体/值对象/领域服务及其不变量。
不碰上下文边界——碰了先回 heartrule-write-spec 的接缝门。

## 6. 异常处理

错误路径、失败模式与处理方式。

## 7. 人工审查清单（验收时逐项打勾）

- [ ] 领域模型片段与意图一致
- [ ] GWT 正例/负例覆盖完整
- [ ] …（story 特有审查项）
```
