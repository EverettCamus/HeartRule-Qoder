# 设计文档治理 / 封板（开发节奏系统 §6 载体与治理）

**核心原则**：文档必须封板——封板即**停止积累**，修订仅证据驱动（展开见步骤 3）。依据：`docs/process/development-rhythm.md` §6。

## 何时用

- 创建/修改 `docs/design/`、`docs/ddd/`、`docs/process/` 下的文档
- 做架构决策（需要 ADR）
- `[design]` story（story-flow 类型分叉转来）

**何时不用**：文档内容的讨论（`heartrule-mechanism-flow`）；story 执行（`heartrule-story-flow`）；不动 status 与决策的小修（改错字、补链接）——直接改，行文仍按下方《表达原则》对。

## 步骤

1. **状态机**：`status` 只取四态——`draft`（成形中）/ `active`（活文档）/ `decision-recorded`（封板，停止积累）/ `superseded`（被取代）。
2. **新文档登记索引**：设计类登记 `docs/design/README.md`，过程类登记 `docs/process/README.md`（活文档，`active` 为常态，不封板，按 §10 演进）；列与层值按各 README 现有写法。
3. **封板**：关键决策落 ADR 后 `active` → `decision-recorded`，**停止积累**——新想法另起 ADR / 新文档 / backlog 探索项；修订仅**证据驱动**（实现碰壁、e2e 暴露问题、领域理解深化），改完重新封板。
4. **ADR 流程**：AI 起草（模板 `references/adr-template.md`）→ **人批准** → 落 `docs/design/decisions/NNN-slug.md`（编号 = 现有最大 +1）→ 更新 README「已记录决策」列 → 更新 `docs/design/architecture-constraints.md`（红线增删需人确认）。
5. **[design] story**（不走六步）：一致性检查（文档概念与 UL/本体对得上）→ 关键决策补 ADR → 封板。

## 表达原则（写或改文档时逐条对）

**读者不该先学一套词汇表，才能读懂这个机制。**

**一、一名一物。**名字定死后，文档、UL、代码三处写同一个标识，每次出现都写全。（例：`判定字段` 就叫判定字段，不叫"判定行 / 首行"，也不省略成"判定"。改了名要**全稿扫**：提示词正文与代码注释最容易漏。）

**二、非主题词不许造。**核心词（`记忆 / 检索词 / 变量 / 话题 / 判定`）出现多少次都不累；机制的**副产品**不该有名字——判据是"它会不会在别处被引用"（UL 词条 / 代码标识符 / ADR / 文档标题）：不会，就用句子说清，做完就丢。

**三、新词先例后名。**先把一句话和一个具体例子说清它在干什么，再命名。名字是**省字的**，不是**省事的**。〔一 / 二 / 三 是一条流水线：要不要起名 → 起就先给例子 → 定了不许换。〕

**四、单一出处。**同一事实只说一处，别处给指针。文档自相矛盾比一段话读着累严重——读者是照着它建代码的。（红线层同类：`architecture-constraints.md` A5「UL 单一出处」。）

**五、版式两种。**元信息（"待实测 / 见附 X / 案例 N / ⚠️ 待定"）进句尾括号或章末小表，不夹在句子中间，且必须带归宿（backlog 探索项 / 附录 / ADR 草稿）——正文不留裸 ⚠️；表只用于**同类多项对照**、第一列是检索键，单点陈述与递进论证用句子（反例：两列一行的表 = 句子）。

**六、正文只讲这个东西本身。**沿革与"跟上一版比变了什么"进附录或评审包，正文不留悬空引用。

**章也按这个道理立**：标题名副其实——「总体流程」里不塞设计原则和边界；一章不塞两件事。（产出物层见下方《产出物规则》。）

**冲突时**：读者的检索与实现正确性 > 阅读流畅。

## 人审门（停止点）

ADR 与领域模型变化需人批准。

## 产出物规则（§4 住所）

ADR 的下一个读者是**每次开工的 AI 与封板评审的人**，住所 = `docs/design/decisions/`；文档状态的下一个读者是所有读者，住所 = README 索引。

## 常见违规与 Red Flags

| 违规想法                       | 现实                                          |
| ------------------------------ | --------------------------------------------- |
| "再往封板文档里加一小节"       | 封板 = 停止积累；新想法另起 ADR/新文档/探索项 |
| "顺手把状态改了，索引以后再说" | 状态改了索引没改 = 账不符                     |
| "这个决策小，不用 ADR"         | 关键决策落 ADR 是封板的前提；§6 状态语义写明  |

- ADR 未经人批准就落 `decisions/`
- 给机制的**副产品**起名字，或一个东西两个称呼（表达原则一 / 二）
- 同一事实在正文里出现两次，或正文里讲来路（表达原则四 / 六）
