# DDD 合规自查报告格式

> story-flow 第 5 步（实现与测试）完成后填写。检查依据：`docs/design/architecture-constraints.md`（**该文件尚不存在**——首次需要时创建并登记进 `docs/design/README.md` 索引，层归属 = 横切约束）。

报告四栏：

| 栏            | 内容                                                                                  |
| ------------- | ------------------------------------------------------------------------------------- |
| 新增概念/接口 | 本次实现新增的类、枚举、字段、端口、路由等清单                                        |
| UL 对照       | 每个新增概念是否已登记 UL（`docs/design/ubiquitous-language.md`）；未登记的逐条补登记 |
| 约束违反      | 对照架构约束清单逐条自查；如有违反，先报告再修                                        |
| 层依赖变化    | 限界上下文/包之间的依赖关系是否有变化（新增依赖、方向反转等）                         |

**人审方式（§7 第 5 步）**：机械项（名字登记了没、约束违反了没）AI 自查可靠；语义项（"换马甲另起炉灶"）不可靠——人抽查报告里的**新增项**。
