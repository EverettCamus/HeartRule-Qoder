# 机制讨论收敛（开发节奏系统 §8 专家系统建模）

**核心原则**：引擎智能机制**讨论事件驱动、产出物受排期约束**——每次讨论必须五落点收敛，收敛出的实现 story 一律进 backlog 由 sprint 排期，不许"顺手实现"。节奏依据：`docs/design/development-rhythm.md` §8。

## 何时用

- `[intelligence]` story（story-flow 类型分叉转来）
- 引擎级需求（§3 三分类的第三类）
- 任何智能机制讨论：记忆调取、意识触发、队列调整等的**实现方式**

**何时不用**：平台业务需求（§3 前两类，走 DDD/六步）；已定机制的执行（走 `heartrule-story-flow`）。

## 步骤

1. **本体先行（操作上 = 先到任务层找锚）**：新任务挂到已有任务；挂不上先补任务层条目（`docs/design/ontology.md` §1），再补领域层概念（§2 概念表带**任务锚**列），然后才设计机制。**任务锚纪律**：每个新概念必须回答"哪个任务需要它"——写不出来就是造词，不进本体。
2. **机制设计**：认知任务分析——触发条件、判断依据、干预方式；结构化为参数（冷却时间、上下文窗口、干预模式等）。推理层判断落 ontology.md §3。
3. **案例验证**：AI 起草模拟对话片段，**人确认合理性后使用**（单一出处）；案例在验收处必出现。
4. **五落点收敛**（§8 产出物规则；习惯称"四选一"，落点实为五种——§13 名词表），每次讨论至少落一处：
   1. **本体文档更新** → `docs/design/ontology.md`（补了任务层/领域层/推理层条目）；
   2. **机制设计文档** → `docs/design/` 对应文档——开头必写**引擎级业务需求一句话**（可追溯性闸门：谁在什么场景得到什么价值；写不出来 = 技术自嗨，不写）；
   3. **ADR** → `docs/design/decisions/NNN-slug.md`（格式见 `heartrule-design-docs` 的 `references/adr-template.md`）；
   4. **spec** → `docs/superpowers/specs/`（锚 + 任务锚写开头，机制说明写设计段；同一机制复用出第二个场景时**必须提炼回机制文档**）；
   5. **backlog 故事** → `[intelligence]` 条目。
   - 收敛不出 → backlog「智能设计议题」表（`| 议题 | 未决问题 | 备注 |`）记**探索项**，注明未决问题，下次继续——不允许"无产出地聊到哪算哪"。

## 人审门（§4 协议表四连）

1. 任务分解符合咨询实践（任务锚）；
2. 机制是否真捕获咨询智慧；
3. 案例合理性；
4. 验收结论。
   每处产出前停下等人确认。若 ontology.md 的任务层仍为 `draft`（§5 开放问题待审），挂锚结论连同该 draft 条目一起提交人审——draft 获确认前不继续机制设计。

## 纪律

- **复用优先**：引入成熟机制（RAG、知识图谱等）先找现成的，不从零造。
- **讨论不许顺手实现**：收敛出的实现 story 一律进 backlog，由 sprint 排期。
- **推翻/大改已有机制前先出两份现状说明**：静态（有哪些组件、各自干什么、怎么关联）+ 动态（关键场景里组件怎么交互），人验证正确后再动手改。
- 机制文档成熟（案例验证通过 + 人确认可拆）后拆成 `[feature]` 故事流入 sprint。

## 可选引用

仓库已有 `memory-plan` agent（记忆方案评估）——机制讨论涉及记忆系统时可用，不重复其职责。

## 常见违规（rationalization 表）

| 违规想法                       | 现实                                                     |
| ------------------------------ | -------------------------------------------------------- |
| "这个机制想清楚了，直接实现吧" | 产出物受排期约束——实现 story 进 backlog，sprint 定了才做 |
| "这个概念先造出来再说"         | 无任务锚不进本体——先回答"哪个任务需要它"                 |
| "讨论先记个大概，下次再整理"   | 每次讨论必须收敛落点；收敛不出就记探索项（含未决问题）   |
| "机制直接写 spec，本体不用动"  | 本体先行——任务层缺口先补 ontology.md，再谈机制           |

## Red Flags

- 讨论结束没有任何落点产出
- 新概念没写任务锚就进本体
- 机制文档开头没有引擎级业务需求一句话
- 讨论过程中就开始改代码
